# LCD 按键小游戏：陨石守卫

当前工程上电后进入游戏标题画面。按 **K4** 开始，控制飞船躲避并击碎陨石。

| 开发板按键 | 引脚 | 功能 |
| --- | --- | --- |
| KEY-1 / SW3 | PF8，低电平按下 | 长按向左移动 |
| KEY-2 / SW4 | PF9，低电平按下 | 长按向右移动 |
| KEY-3 / SW5 | PF10，高电平按下 | 长按连续发射子弹 |
| KEY-4 / SW6 | PF11，高电平按下 | 开始 / 暂停 / 继续 / 游戏结束后重开 |

接线依据是 `SCH_ZET6开发板.pdf` 第 8 页。K1、K2 使用内部上拉，K3、K4 使用内部下拉；四个按键各自有 20 ms 消抖，支持边移动边发射。游戏自行初始化 GPIOF，无需另接按键或修改 CubeMX 配置。

## 玩法

- 初始 3 条命，碰到陨石扣 1 条命；受击后有 1.2 秒闪烁无敌时间。
- 每击碎一个陨石得 10 分，每存活 1 秒得 1 分。
- 每 100 分增加难度，最高 9 级，陨石会更快、更密集。
- `SCORE` 是当前分数，`LIFE` 是剩余生命，`LV` 是当前难度。
- 游戏结束显示本次通电期间的最高分；按 K4 重开会保留最高分，断电或复位会清除。

## 编译、烧录

1. 打开 `MDK-ARM/LCD_hal.uvprojx`，目标选择 `LCD_hal`。
2. 点击 Build（F7），然后 Download（F8）。
3. 烧录后若没有自动运行，按开发板复位键，上电画面应为 `METEOR GUARD`。

本次已经使用本机 Keil ARMCC 5 编译通过，0 错误、0 警告。

- 烧录文件：`MDK-ARM/LCD_hal/LCD_hal.hex`
- 调试文件：`MDK-ARM/LCD_hal/LCD_hal.axf`
- 构建日志：`MDK-ARM/game_build.log`
- 固件 ROM：27,380 字节，约 26.74 KiB。
- 全工程静态 RAM（含链接器预留栈和堆）：2,168 字节，约 2.12 KiB。

代码已编译并通过主机模拟检查，尚未在实物开发板上验证按键手感、屏幕方向及实际刷新速度。

## 文件和调整方式

- `Core/Src/main.c`：LCD 初始化后调用 `LCD_GameInit()`，主循环调用 `LCD_GameTask()`。
- `Core/Src/board_keys.c`：按键引脚、有效电平、消抖和按下事件。
- `lcd/meteor_game.c`：移动、子弹、陨石、碰撞、生命、计分和难度。
- `lcd/lcd_game.c`：标题、游戏画面、暂停、结束画面和原创像素飞船/陨石素材。
- `lcd/meteor_game.h`：`METEOR_FRAME_MS` 默认 40 ms，目标 25 次更新/秒。
- `assets/game/`：由实际 C 绘图代码和工程字库生成的画面预览。

每帧只擦除旧的物体区域，再绘制新位置；没有使用整屏 RAM 缓冲。前面的小猫动画和图片文件仍保留在工程中，游戏不引用它们，因此链接器会去掉其未使用数据。

要切回小猫动画，在 `main.c` 将 `lcd_game.h` 换回 `lcd_animation.h`，并把两个游戏入口换回 `LCD_AnimationInit()` / `LCD_AnimationTask()`，再重新编译即可。

## 主机验证和预览

在工程根目录运行（需要 GCC 和 Pillow）：

```powershell
python tools/test_game.py
```

检查包括：按键极性与上下拉、抖动过滤、多键同按、计时器回绕、移动边界、子弹命中、扣血、无敌、暂停冻结、重开保留最高分、8 万步逻辑模拟，以及横竖屏实际绘图坐标。该脚本不连接或烧录开发板。
